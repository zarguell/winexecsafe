# WinExecSafe - Windows AppContainer Process Jail Wrapper

A C++ command-line wrapper that launches any target executable within a Windows AppContainer sandbox, restricting filesystem access to a designated jail directory while allowing system binaries to execute normally.

## Features

- **Kernel-level isolation** using Windows AppContainer technology
- **Filesystem jail** - restricts read/write operations to a specific directory
- **System command execution** - allows cmd.exe, PowerShell, and other system binaries to run normally
- **Network capability control** - optional network access permissions
- **Flexible configuration** - via INI file or command-line arguments
- **No virtualization required** - works on Windows 8+ without Docker or VMs
- **Automatic cleanup** - removes AppContainer profiles after execution

## Building

### Prerequisites

- Windows 8 or higher (Windows 10/11 recommended)
- Visual Studio 2019 or later with C++ support, OR
- CMake 3.15+ and a Windows C++ compiler

### Build with CMake

```bash
mkdir build
cd build
cmake ..
cmake --build . --config Release
```

The executable will be located at `build/bin/winexecsafe.exe`.

### Build with Visual Studio

1. Open the solution file generated by CMake, or
2. Create a new C++ Console Application project and add `main.cpp`
3. Link against `userenv.lib` and `advapi32.lib`
4. Set character set to Unicode
5. Build in Release mode

## Usage

### Command-Line Mode

Run any executable with minimal arguments:

```cmd
winexecsafe.exe --executable "C:\Windows\System32\cmd.exe" --args "/c echo Hello" --jail-dir "C:\MyJail"
```

With more options:

```cmd
winexecsafe.exe --executable "C:\path\to\app.exe" ^
  --args "--option1 value1 --option2" ^
  --jail-dir "C:\Sandbox" ^
  --working-dir "C:\Sandbox\work" ^
  --allow-network ^
  --container-name "MyContainer" ^
  --verbose
```

### Configuration File Mode

Create a config file (e.g., `config.ini`):

```ini
[General]
Executable=C:\Windows\System32\cmd.exe
Arguments=/c echo Hello from jail!
JailDirectory=C:\WinExecSafeJail
WorkingDirectory=C:\WinExecSafeJail\work
ContainerName=MyAppContainer
AllowNetwork=false
Cleanup=true

[Permissions]
AdditionalReadPaths=C:\Program Files\MyApp;C:\SharedData

[Logging]
Verbose=true
LogFile=C:\ProgramData\winexecsafe\logs\wrapper.log
```

Then run:

```cmd
winexecsafe.exe --config config.ini
```

### Mixed Mode

Use command-line arguments to override config file settings:

```cmd
winexecsafe.exe --config config.ini --verbose --no-cleanup
```

## Command-Line Arguments

| Argument | Description | Required | Default |
|----------|-------------|----------|---------|
| `--config <path>` | Path to INI configuration file | No | `C:\ProgramData\winexecsafe\config.ini` |
| `--executable <path>` | Full path to target executable | Yes* | - |
| `--args <string>` | Arguments for target executable | No | - |
| `--jail-dir <path>` | Jail directory path | Yes* | - |
| `--container-name <name>` | AppContainer profile name | No | Auto-generated |
| `--working-dir <path>` | Working directory inside jail | No | Jail root |
| `--allow-network` | Grant network capabilities | No | false |
| `--cleanup` | Delete profile after execution | No | true |
| `--no-cleanup` | Keep profile after execution | No | false |
| `--verbose` | Enable verbose logging | No | false |

*Required if not specified in config file

## Configuration File Format

The INI file is divided into three sections:

### [General]

Main execution settings:

- `Executable`: Path to the target executable
- `Arguments`: Command-line arguments to pass
- `JailDirectory`: Directory where process can read/write
- `WorkingDirectory`: Working directory (defaults to jail root)
- `ContainerName`: Unique AppContainer profile name
- `AllowNetwork`: true/false to enable network access
- `Cleanup`: true/false to delete profile after execution

### [Permissions]

Additional filesystem permissions:

- `AdditionalReadPaths`: Semicolon-separated list of directories to grant read/execute access

### [Logging]

Logging options:

- `Verbose`: true/false for detailed logging
- `LogFile`: Path to log file (optional)

## How It Works

1. **Configuration Loading**: Loads settings from config file and/or command-line arguments
2. **Profile Creation**: Creates or retrieves an AppContainer profile
3. **Permission Granting**: 
   - Grants full access to the jail directory
   - Grants read/execute access to System32 and SysWOW64
   - Grants read/execute to any additional paths from config
4. **Capability Building**: Adds network capabilities if enabled
5. **Process Launch**: Creates process in AppContainer with restricted access
6. **Execution**: Waits for process to complete and returns exit code
7. **Cleanup**: Removes AppContainer profile and frees all resources

## Security Model

The jail enforces the following restrictions:

- **Read/Write**: Only the jail directory and its subdirectories
- **Read/Execute**: System directories (System32, SysWOW64) and any additional paths from config
- **Network**: Disabled by default, can be enabled with `--allow-network`
- **Registry**: Restricted to AppContainer-specific registry hive
- **IPC**: No inter-process communication outside the container

## Examples

### Run cmd.exe with a simple command

```cmd
winexecsafe.exe --executable "C:\Windows\System32\cmd.exe" --args "/c dir" --jail-dir "C:\Jail"
```

### Run a custom application with network access

```cmd
winexecsafe.exe --executable "C:\MyApp\app.exe" --jail-dir "C:\Sandbox" --allow-network --verbose
```

### Run with configuration file and override settings

```cmd
winexecsafe.exe --config "C:\configs\sandbox.ini" --verbose --container-name "TestRun"
```

### Run Python script (requires Python in read paths)

```ini
[General]
Executable=C:\Python39\python.exe
Arguments=script.py
JailDirectory=C:\Sandbox

[Permissions]
AdditionalReadPaths=C:\Python39;C:\MyScripts
```

## Troubleshooting

### "Executable file does not exist"

Ensure the executable path is absolute and the file exists:
```cmd
winexecsafe.exe --executable "C:\Windows\System32\cmd.exe" --jail-dir "C:\Jail"
```

### "Failed to create AppContainer profile"

Run as Administrator or use a different container name:
```cmd
winexecsafe.exe --executable "app.exe" --jail-dir "C:\Jail" --container-name "UniqueName"
```

### Process can't access system binaries

Add the required directory to `AdditionalReadPaths` in the config file:
```ini
[Permissions]
AdditionalReadPaths=C:\Program Files\MyApp
```

### Access denied errors

Ensure you have appropriate permissions to:
- Create/modify the jail directory
- Create AppContainer profiles (usually requires Administrator rights)
- Modify ACLs on the jail directory

## Limitations

- Windows-only (requires Windows 8+)
- AppContainer profiles require Administrator privileges to create
- Some applications may not work correctly in an AppContainer (e.g., those requiring full system access)
- Registry access is limited to AppContainer-specific hives
- Named pipes and other IPC mechanisms are restricted
